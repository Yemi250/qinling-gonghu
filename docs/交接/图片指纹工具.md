## 1. 定位与边界（先读这一节）

本工具是**重复/近似图片识别的候选筛选工具**，只回答一个问题："哪些图片的字节完全相同？哪些图片在 64 位 dHash 意义上结构相近？"

它**不能**做以下事情，任何使用方都不得越界解读：

- 不能证明照片真实性（指纹相同 ≠ 照片真实）；
- 不能证明两张图属于同一事件（同一事件的配图可能不同，不同事件的图可能碰撞）；
- 不能区分不同游客身份；
- 不能把汉明距离换算为模型置信度、重复概率或事件真实性概率；
- 不制定自动合并规则——是否合并、如何合并由总工程师负责的模块决策，本工具只提供候选信号。

工具本身只使用 Pillow 与 Python 标准库；不访问网络、不读取 `.env`、不调用模型、不读取数据库、不修改原图文件。

## 2. 接口

### 2.1 `ImageFingerprint`

```python
@dataclass(frozen=True)
class ImageFingerprint:
    sha256: str    # 文件当前实际字节的 SHA-256，64 位小写十六进制
    dhash: str     # 64 位差异哈希，16 位小写十六进制
    width: int     # 解码后图片实际宽度（像素）
    height: int    # 解码后图片实际高度（像素）
```

不可变值对象，同输入必相等。`sha256` 与 `uploads` 表存储值同源同算法（见 3.1）；`dhash` 仅作近似重复的候选筛选信号。

### 2.2 `compute_fingerprint(path: Path) -> ImageFingerprint`

```python
from backend.app.image_fingerprints import compute_fingerprint

fp = compute_fingerprint(Path("data/images/<image_id>.jpg"))
print(fp.sha256, fp.dhash, fp.width, fp.height)
```

输入是**已经由现有系统规范化并落盘**的图片路径（`uploads.normalize_image` 产物：EXIF 已转正、RGB、JPEG quality=90）。函数不重新编码、不做二次规范化、不补做 EXIF 转正；喂入其他图片时按"当前文件字节"如实计算。

实现上一次读入文件字节，SHA-256 与 dHash 保证来自同一份字节，避免"哈希与指纹来自不同版本文件"的错位。

### 2.3 `hamming_distance(left: str, right: str) -> int`

```python
from backend.app.image_fingerprints import hamming_distance

hamming_distance("0020302c0c0c0c01", "0020302c0c0c0c01")  # 0
hamming_distance("0" * 16, "f" * 16)                       # 64
```

两个恰好 16 字符的十六进制串（大小写均可）的按位异或 1 计数，返回 0–64。0 表示 64 位全部相同，64 表示全部相反。

### 2.4 异常行为（绝不静默返回伪造指纹）

| 场景 | 异常 | 说明 |
|---|---|---|
| `path` 不存在 | `FileNotFoundError` | 由字节读取自然抛出 |
| `path` 是目录 | `IsADirectoryError`（`OSError` 子类） | |
| 其他读取 I/O 错误 | `OSError` | |
| 文件存在但无法解码（空文件、非图片内容、损坏、截断） | `ImageUnreadableError`（本模块定义，继承 `Exception`） | 原始解码异常（`UnidentifiedImageError` / `OSError` / `ValueError`）保留在 `__cause__` |
| `hamming_distance` 参数不是字符串 | `TypeError` | |
| `hamming_distance` 长度不是 16 或含非十六进制字符（含 `0x` 前缀、下划线、空白） | `ValueError` | 不静默当作 0 距离 |

`ImageUnreadableError` 是本模块对外唯一的自定义异常类型，调用方可以只捕获 `FileNotFoundError` 与 `ImageUnreadableError` 两类处理文件问题。

## 3. 算法规格

> dHash 定义一经上线即冻结，不得再改动；否则历史指纹与新指纹之间不可比较，等于全部作废重算。

### 3.1 SHA-256

对文件**当前实际字节**直接计算 `hashlib.sha256(data).hexdigest()`，不做任何重新编码。因此对 `uploads` 表保存的同一个文件，本工具算出的 `sha256` 与 `uploads.sha256` 完全一致——字节级完全重复直接用这张表就能查出来，本工具的 `sha256` 字段保证与它对得上。

### 3.2 dHash（固定 64 位）

1. 用 Pillow 转灰度（mode `"L"`，ITU-R 601-2 亮度：`L = 299R/1000 + 587G/1000 + 114B/1000`）；
2. 用 LANCZOS 重采样缩放到 9 列 × 8 行；
3. 每一行自左向右比较相邻像素：左像素 > 右像素记 1，否则记 0；共 8 行 × 8 位 = 64 位；
4. 按行优先顺序、首个比较结果作为最高有效位打包成 64 位整数，编码为 16 位小写十六进制。

位序示意（行内 8 个比较结果即该行的 8 个二进制位，行 0 为最高字节）：

```
位序：row0: [c0>c1][c1>c2]...[c7>c8]  ← 最高字节
      row1: 同上
      ...
      row7: 同上                      ← 最低字节
示例：偶数列亮、奇数列暗的 9×8 图，每行比较结果为 10101010 = 0xAA，
      8 行全同 → dHash = "aaaaaaaaaaaaaaaa"
```

整条链路确定性：同字节文件在任何环境重算结果逐位一致。测试已验证 9×8 灰度图上 LANCZOS 同尺寸缩放为恒等映射，因此 9×8 无损图上的指纹可手工推导核对（测试第 4 组即这么做）。

## 4. 实测数据

以下数值全部由本仓库测试环境实测（Python 3.12.7 + Pillow 12.3.0，确定性构造样例）。**这些是观察记录，不是合并阈值，不得直接当判据使用。**

### 4.1 同图变体与不同图（800×600 渐变 + 几何形状样例，参考图 dHash `0020302c0c0c0c01`）

| 对比样例 | 汉明距离 | 解读 |
|---|---|---|
| 同尺寸重编码 JPEG q95 | 0 | 压缩噪声未翻转任何比较位 |
| 同尺寸重编码 JPEG q85 | 0 | 同上 |
| 缩小到 400×300 JPEG q80 | 0 | 缩放后仍逐位一致 |
| 放大到 1600×1200 JPEG q90 | 0 | 同上 |
| 旋转 180° JPEG q90 | **54** | 同一张图！旋转使比较方向反转，距离接近 64 |
| 反色图 JPEG q85 | 64 | 每个比较位翻转 |
| 另一张不同构图的样例 | 23 | 不同图在本样例中距离明显更大 |

样例结论（仅对样例成立，不推广）：本组样例中"同一张图的压缩/缩放变体"距离为 0，"不同构图的图"距离 23。**旋转 54** 说明距离小只是近似重复的必要信号之一：内容相同但视角/方向不同会被判远，人工与真实模型复核不可省。

### 4.2 构造图案两两距离（9×8 无损 PNG，手工推导核对过位序）

| 图案对 | 距离 |
|---|---|
| 竖条纹 / 降阶对角线 | 32 |
| 竖条纹 / 左亮右暗 | 40 |
| 竖条纹 / 上亮下暗 | 16 |
| 降阶对角线 / 左亮右暗 | 14 |
| 降阶对角线 / 上亮下暗 | 20 |
| 左亮右暗 / 上亮下暗 | 24 |

### 4.3 碰撞局限（测试明确证明）

以下**完全不同**的图片共享同一个 dHash `0000000000000000`，而它们的 SHA-256 各不相同：

- 纯白、纯黑、纯红 (255,0,0)、纯灰 (128,128,128) 四张纯色图；
- 黑白水平条纹图（每行内部均匀，比较方向上无变化）。

原因：dHash 只编码"每行内左与右的亮度比较"，一张图只要在 9×8 灰度网格上每行的相邻像素全部相等（纯色、按行均匀），就必然得到全 0。同理，纯亮度平移、对比度缩放等保持大小关系的变换也不会改变 dHash。**相同 dHash 不能推出相同照片，更不能推出同一事件或同一游客。**

## 6. 给总工程师的集成注意事项

1. **字节级完全重复不用本工具**：`uploads.sha256` 等值查询即是精确答案；本工具的 `sha256` 字段与它一致，可用于核对。
2. **近似候选筛选**：对规范化后的文件批量 `compute_fingerprint`，dHash 汉明距离小的对进入候选列表，再交人工或真实视觉模型复核。批量计算、存储方案（新表或新列）与触发时机属于总工程师的数据库与合并策略范围，本工具不读取也不修改数据库。
3. **不要自动合并**：4.3 的碰撞与 4.1 的旋转样例说明，任何"距离 ≤ N 就自动合并"的规则都会出错（同图旋转判远、不同纯色图判同）。距离只能缩小候选范围。
4. **不要换算置信度**：汉明距离是位差异计数，与"同一事件概率"没有标定关系。
5. **算法冻结**：dHash 定义（灰度 → LANCZOS 9×8 → 行内左大于右 → 行优先 MSB 打包）一旦有指纹落库即冻结；将来若要换算法，应新增字段而不是改写本函数语义。
6. **输入契约**：`compute_fingerprint` 只接受已规范化落盘的文件路径；不要对用户原始上传流喂未规范化文件（EXIF 方向未转正会导致方向不同的同图指纹不一致）。
