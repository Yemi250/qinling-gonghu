# 游客体验升级：山河护照、任务笺与共护勋章

本轮沿用已认可的陕西水墨地图、暖纸页面和六景区独立配色，扩展游客参与旅程：公开浏览 → 注册参与 → 领取线上探索印记 → 收藏记忆或提供共护材料 → 接收治理回音 → 查看守护值和勋章。没有新增投诉墙、排行榜、积分兑换、聊天向导或地理签到。

## 使用路线

地图与六个景区介绍不要求登录。导航仍为“陕西漫游、秦岭专栏、我的足迹”，右侧显示游客是否登录；“我的足迹”进入山河护照。游客账号与景区工作台的管理账号相互独立。

点击景区“留住这一刻”“一起照看这里”或任务笺的领取印记，会打开注册登录纸笺。注册填写用户名、密码、确认密码和昵称；已注册用户切换到登录。成功后仍在原景区，继续刚才选择的操作。未登录不上传图片。

每景区有三个任务。领取探索印记是一项明确的线上操作，不是地理签到；保存明信片完成风景记忆；共护是可选的，遇到需要照看的地方再提供材料，经人工审核后才成为有效贡献。任务进度来自服务端，不用前端计时或点击次数模拟完成。

投稿保存到账号后，界面读取已有 EcoProof 四阶段分析、实际失败与重试状态、共护处理时间线，以及归并后的共同回音。账号失效时重新登录，同一账号的照片预览和文字保留；补充草稿仅存当前应用内存。显式退出或改用另一账号会清空上一个账号的界面和草稿。多标签页只广播会话发生变化，再各自向服务端读取身份，不广播会话密钥。

## 四视图护照

| 视图 | 具体内容 |
|---|---|
| 我的旅程 | 昵称、守护值、探索/记忆/有效贡献/结案数量、六景区印记、尚可参与的任务 |
| 风景记忆 | 当前账号的私密收藏，按景区过滤后分页；点击读取明信片 |
| 共护回音 | 当前账号原始投稿，包含补充事项、EcoProof 和实际处置进展 |
| 勋章册 | 六枚原创 SVG 勋章，服务端解锁条件、进度及获得时间；可展开增减明细 |

探索、收藏、参与数量不等于治理效果。投稿数量、重复照片数量不转写为公众人数。页面保留示范原型与景区尚未接入的标识。

## 守护值规则与回算

| 行为 | 守护值 | 限制 |
|---|---:|---|
| 主动领取探索印记 | +5 | 每账号、每景区一次 |
| 保存风景记忆 | +10 | 每账号、每景区一次；同一规范化 JPEG 不跨景区重复奖励 |
| 经人工确认的有效共护 | +20 | 每账号、每当前治理事件一次；重复照片不是独立贡献 |

探索使用唯一键防止重复领取。记忆按已保存的照片字节 SHA-256 核对该账号既有照片，而不是用 dHash 相似度当作独立性概率。共护图片的独立性在全体投稿中按规范化照片哈希及首次材料提交顺序判断；后补图片不会借用旧事件的创建时间抢走先前投稿的独立依据。

根投稿人工审核通过并派单即视为有效审核；归并子投稿必须逐份确认 `accepted`。只有关联成功、上传成功、分析成功、补充材料或刷新页面，都不直接奖励共护。主事件必须已进入处理、待验收或人工结案，材料必须有独立依据，投稿必须有账号归属，才能计入有效贡献。同账号在一个归并事件中有多份有效材料仍只奖励一次。

管理员在原有事件详情内查看贡献条件、填写依据并确认或纠正审核，不增加管理页面。重复照片不能在界面确认为独立贡献；服务端即使收到 `accepted`，也不会为重复图增加奖励。原匿名投稿未导入时不归属任何游客账户，不发放账号奖励。

创建、探索、派单、贡献审核、归并、撤销归并和旧记录导入，会在同一数据库事务内重新核对奖励及勋章。失去条件的奖励停用，并写入负数调整；恢复条件写入正数调整；历史记录不删除。已经结案的关联不能撤销或自动重开，但管理员仍可纠正贡献审核和对应奖励。

## 六枚原创勋章

| 标识 | 勋章 | 图案 | 解锁条件 |
|---|---|---|---|
| departure | 山河启程 | 山形 | 探索首个景区 |
| collector | 风景收藏家 | 镜头 | 保存首张明信片 |

图案在 `frontend/src/features/passport/BadgeArt.tsx` 中以原创 SVG 路径制作，不新增图像生成或外部素材依赖。低饱和金属纹理使用向量渐变、描边与阴影。已解锁与未解锁采用不同明度，进度条直接使用服务端数据；失去条件时勋章恢复锁定，调整依据仍在明细中。新解锁显示短暂盖章动效的勋章提示，可主动收起；系统设置减少动态效果时直接显示结果。

## 身份、权限与接口

用户名为大小写不敏感的 3–32 位 ASCII 字母、数字或下划线；昵称支持中文；密码 8–128 位。密码采用独立 16 字节随机盐与 PBKDF2-HMAC-SHA256/600000 次派生，避免复用管理员演示账号的校验方法。依据：[OWASP 密码存储说明](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html)。

游客使用七日 HttpOnly、SameSite=Lax Cookie，路径 `/api`。HTTPS 请求自动设置 Secure，反向代理部署可显式配置 `VISITOR_COOKIE_SECURE=true`，并正确传递 HTTPS 请求信息。游客写请求验证同源及 `X-Gonghu-CSRF`；注册登录验证同源，各接口按 IP 每分钟限制十次尝试。限流针对当前单 worker，重启会清空内存限流状态。

| API | 说明 |
|---|---|
| POST /api/visitor/register、/login | 注册登录，返回 user 与 csrf_token，并设置游客 Cookie |
| POST /api/visitor/logout | 撤销当前游客会话，返回204；不改变管理员会话 |
| GET /api/visitor/me | 匿名可调用；返回当前 user 与 csrf_token，可空 |
| GET /api/visitor/me/passport | 当前账号 summary、六景区 tasks 和六枚 badges |
| POST /api/visitor/explore/{scenic_id} | 幂等领取线上印记，返回最新护照 |
| GET /api/visitor/me/records | kind、scenic_id、limit、offset，按账号及过滤条件先查询后分页 |
| GET /api/visitor/me/rewards | 分页增减明细，含 delta、label、note、created_at |
| POST /api/visitor/me/import | 主动提交旧记录 `{id,kind,query_token}`，逐项确认归属，不转移已绑定记录 |
| GET/POST /api/events/{id}/contribution | 仅管理员 Bearer；读取条件，使用新 revision 与非空 note 审核或纠正 |

完整模型与字段在 [OpenAPI](openapi.json) 和 [API 清单](API.md)。既有收藏、投稿、补充、分析路径保留；新记录和上传必须登录，并按账号归属校验。创建响应保留原 query_token 字段用于契约兼容，但新记录的 token 不能绕过账号权限。

管理员登录另外设置专用图片 Cookie，作用仅为图片读取；管理 API 仍需要 Bearer，游客会话和图片 Cookie 都不授予管理权限。新游客图片由所属账号或管理员读取；同一治理事件的参与账号可读该事件的整改图片，其他游客原始材料仍相互隔离。响应使用 private/no-store。历史匿名图片维持原随机链接兼容方式。

## 迁移和旧记录

数据库从版本1或2升级至3前，使用 SQLite 在线 backup 生成 `DATA_DIR/backups/before-v3-*.sqlite3`。版本3增加账户、游客会话、探索、贡献审核、奖励与调整、勋章表；事件、明信片与上传增加可空归属或访问方式。不改变原材料文件、凭证、旧路由与历史时间线。

新账号的内容完全以服务端归属为准。原浏览器本地凭证不会自动当作该账号的记录。发现旧凭证时，在护照内提供“导入我的护照”，用户主动确认后提交后端验证。凭证正确且记录尚无归属或已属于当前账号时可导入；无效凭证、已属于其他账号的记录会返回未导入，不泄露归属信息。原匿名编号与凭证找回入口继续保留。

数据库备份不包含图片文件。完整备份仍需停服务后复制全部 DATA_DIR，保留图片及 SQLite 文件；本轮不删除历史数据、孤立图片或失败测试材料。

## 开发和复现

后端核心：`visitor_auth.py`、`visitors.py`、`visitor_models.py`、`rewards.py`。前端组件：`features/passport/`，接线位于 `Journey.tsx`、`Notebook.tsx`、`Records.tsx`、`Workbench.tsx` 和 `App.tsx`。

```text
uv run pytest backend/tests backend/tests_ai -q
uv run ruff check backend scripts
uv run python -m scripts.export_openapi
npm --prefix frontend run generate:types
npm --prefix frontend run build
uv run python -m scripts.smoke
node scripts/passport_browser.mjs
node scripts/browser_smoke.mjs
node scripts/admin_scenic_browser.mjs
```

真实模型验收另行执行 `uv run python -m scripts.live_upgrade_smoke`，需要服务端已配置模型凭据和 Node/Playwright。测试均使用系统临时目录、随机端口及明确标注的测试材料，不向正式演示数据库写入测试记录。模型连接成功只证明真实调用及保存、展示流程，不证明照片真实性或实际整改效果。

本轮不提供短信、邮箱验证、密码找回、实体权益或积分兑换；管理员仍是演示配置账号，没有独立工作人员授权体系。Docker 容器与在线托管未在本轮新增验证。
