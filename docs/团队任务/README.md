## 产品共同目标

产品名：秦岭共护。定位：AI 驱动的景区生态共治平台。主张：**让每一次发现，都有一个回应。**

游客随手拍 → AI 整理 → 管理员派单 → 工作人员提交整改 → AI 对比 → 管理员结案 → 游客反馈。

一个示范景区、垃圾问题为主场景。疑似烟雾、火点、水体异常为可选扩展，复用人工复核流程。真实调用与流程闭环必须保留，不做生产级精度研究，不增加商城、社区或复杂灾害指挥系统。

## 分支与整合

1. 队长将队友加入仓库协作者；每人使用自己的 GitHub 账号并接受邀请。
2. 克隆同一仓库，从最新 main 创建对应工作分支。已有代码放入约定模块，避免直接覆盖公共文件。
3. C 先发布公共工程与接口骨架，A 发布公共视觉规范，其他成员并行开发各自模块。
4. 每完成一个可检查成果就提交并推送，创建目标为 main 的 PR，写明改动、验证方式和待集成项。
5. 队长整合并检查后合并；每天中午和晚上各联调一次，不到最后一天才首次集成。
6. 合并后所有人同步主分支，并将最新主分支合入自己的工作分支；冲突与对应负责人一起解决，不强推覆盖他人历史。
7. 不提交密钥、.env、node_modules 或个人运行数据。保留比赛期间的真实开发提交。

A 负责公共视觉，C 负责接口和类型。变更共享契约时，先更新对应文档，再同步全部受影响成员；四份提示词中的共同约定应一起更新。

## 每天的共同验收

| 时间 | 目标 |
|---|---|
| Day 1 晚上 | 新图片上传、真实 AI 分析、人工派单跑通 |
| Day 2 晚上 | 整改、验收、游客反馈闭环，完成首次彩排 |
| Day 3 | 修复问题、打磨视觉、录视频、完成 PPT 与文档、24:00 冻结核心代码 |
| Day 4 9:30 前 | 提交仓库、运行 Demo、视频、说明文档和 PPT |

若第一天链路未通，暂停额外动画；第二天仍未闭环，取消辅助图表与规划点位效果。数据和模型失败可恢复，图片识别不设生产准确率目标。
