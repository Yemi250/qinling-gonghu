# 陕西漫游与山河共护 · 实现与验收

## 方向与边界

团队：牛来。产品保留“秦岭共护”名称，以“山河漫游 · 一起照看”为对外体验。遵循用户批准的低饱和意境：暖纸、陶土、雾蓝；公众入口先展示陕西山河与景区，随后才引导收藏和共护。当前实现两个可操作篇章，其他地标提供筹备说明，避免用户误以为所有景区都已正式接入。

美景收藏和环境线索分开：收藏生成私密明信片，共护生成可追踪的治理事件。对外文案以照看、接力、回音组织；不提供公共指责、排名或投诉墙。景区工作人员使用工作台，将材料转为可审核、可分派、可验收的处理记录。

## 操作路径

`/#/` → 悬停兵马俑 / 太白山 → `/#/scenic/terracotta` / `/#/scenic/taibai` → 随行手记。

“留住这一刻” → 图片上传 → `POST /api/postcards` → 本地保存访问回执 → `/#/memory/{id}`。页面刷新重新从服务器获取明信片。“我的足迹”提供入口，不构成公开照片流。

“一起照看这里” → 图片上传 → `POST /api/events` → 保存访问回执 → `/#/care/{id}` → 调用真实分析接口 → 展示真实结果或失败说明。服务器材料保存完成后才发起 AI；刷新已有记录不会自动再次消费模型调用。分析请求期间只显示实际请求状态，不用定时动画冒充五个已经完成的处理步骤。

工作台 `/#/workbench`：管理员登录 → 查看分页事件队列 → 要求补充或审核派单 → 上传处理后照片 → AI 前后对比 → 人工验收结案，必要时退回。游客可补充现场描述、刷新时间线与整改照片。管理员会话只在当前浏览器会话保存，真实账号密码来自服务端配置。

- `frontend/src/features/journey/Atlas.tsx`：真实地理边界投影、SVG 纹理裁切、地标与目的地卡片。

- `journey.css`：响应式视觉、动画与减少动态效果偏好。
- `backend/app/postcards.py`：新增独立明信片接口与权限。
- `backend/app/db.py`：增量 postcards 建表，旧库与旧事件保留。
- `backend/app/events.py`：新增两个兵马俑示范点位；太白山篇章沿用秦岭示范点位。
- `scripts/browser_smoke.mjs`：真实浏览器 + 独立服务的验收。测试中不提供模型 Key，真实返回不可用，随后验证人工闭环。

## 使用限制

视觉素材是意境插画，不是现场实拍或地图精细地形。市级边界来自 DataV，地形纹理用于艺术展示。两个可操作篇章均为示范点位。图片链接保留既有随机公开能力链接契约；记录正文与状态受访问凭证保护。游客凭证保存在本浏览器，若要换设备，需要先保存完整编号和凭证；没有身份账号体系来重新签发遗失凭证。

当前为单后端 worker、SQLite 的可运行原型。工作台中的工作人员共用演示管理账号，角色权限不按企业员工分级。真实景区部署和治理成效验证不在此次界面改造的完成声明内。
